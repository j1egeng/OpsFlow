# OpsFlow Frontend

项目总览及 Docker 部署步骤：[简体中文](../README.md) | [English](../README.en.md)

当前部署使用 Nginx 容器提供前端，访问 [http://127.0.0.1:8088/](http://127.0.0.1:8088/)。日常启停、凭据与数据库持久化见 [Docker 部署文档](../deploy/README.md)。下面的 Vite 命令仅用于宿主机开发调试。

React + TypeScript 团队工作台，与同级 `backend` 的真实登录、用户管理、软件服务、事件、变更审批与实施及 Dashboard 接口连接，支持中英文切换。

## 已实现页面

- 登录页：密码显隐、错误反馈、会话恢复、后端连接状态。
- 我的账户：当前用户资料、角色、账号状态、创建及登录时间。
- 管理员用户管理：分页列表、当前页搜索、新建用户、角色编辑、启用和停用确认。
- 软件服务管理：分页目录、后端状态筛选、详情页、新建、编辑、负责人选择及启停确认。
- 事件管理：报告事件、分页列表、状态/严重程度/“分配给我”筛选、服务关联筛选、详情、管理员分派、调查/解决/关闭、调查备注及分页状态历史。
- 变更管理：草稿保存与编辑、关联同服务事件、风险/状态/申请人筛选、提交、批准/拒绝、多轮审批、实施结果和失败事件跳转。
- 运营总览：启用服务、活跃事件、待审批变更、实施成功率、UTC 七日新增趋势、状态分布和最近记录；所有数字来自后端统计。趋势同时提供可展开的数据表。
- 管理员审计日志：操作人 ID、动作代码、对象类型/ID、起止时间组合筛选，数据库分页与每页数量切换；只读详情显示操作人、发生时间及原始 JSON，支持关联服务/事件/变更跳转。
- 中英文切换：登录页、工作台右上角和弹窗中可随时选择“简体中文 / English”；即时切换且保留未提交表单，刷新页面后记住语言。界面、已知后端错误、提示、角色及日期格式随语言变化，用户姓名和服务资料保持原文。
- 权限路由：开发者与审批人可查看个人账户和服务目录；管理员还可管理用户、创建/修改/启停服务，以及查询审计日志。后端负责最终权限判断。
- 登录失效处理：过期或受保护接口返回 401 时清理会话并返回登录页。
- 适配桌面与手机的布局、加载状态、空状态和错误重试。

核心业务页面已实现。不会在正常开发服务器中注入演示服务、事件、变更或测试用户。

## 宿主机开发调试（可选）

需要 Node.js 22+。已选择兼容当前电脑 Node 22.9 的 Vite 6.4 维护版本，并通过 lockfile 固定实际安装依赖。

先启动后端，并确认 `http://127.0.0.1:8080/actuator/health` 返回 UP。然后在 `frontend` 目录运行：

```powershell
npm.cmd install
npm.cmd run dev
```

浏览器打开 `http://127.0.0.1:5173`。默认固定使用 5173，避免自动换端口后与后端跨域配置不一致。

登录使用自己初始化的管理员或管理员创建的账号。没有前端预置账号、注册接口或默认密码。首次管理员初始化见 [后端说明](../backend/docs/auth-users-api.md)。

后端运行在其他地址时，将 `.env.example` 复制为 `.env.local` 并修改：

```dotenv
BACKEND_URL=http://127.0.0.1:8080
```

修改后重启 Vite。该地址仅用于开发/预览代理，不将数据库密码、管理员密码或 JWT 签名密钥放入前端环境变量。

## 接口连接

| 页面功能 | 后端接口 |
| --- | --- |
| 登录 | `POST /api/v1/auth/login` |
| 当前账户与角色刷新 | `GET /api/v1/auth/me` |
| 分页用户列表 | `GET /api/v1/users?page=0&size=10` |
| 新建用户 | `POST /api/v1/users` |
| 替换角色 | `PUT /api/v1/users/{id}/roles` |
| 启用/停用 | `PATCH /api/v1/users/{id}/status` |
| 软件服务目录（可选 enabled 筛选） | `GET /api/v1/services?page=0&size=10` |
| 服务详情 | `GET /api/v1/services/{id}` |
| 创建服务 | `POST /api/v1/services` |
| 完整替换服务资料及负责人 | `PUT /api/v1/services/{id}` |
| 服务启用/停用 | `PATCH /api/v1/services/{id}/status` |
| 事件分页、筛选 | `GET /api/v1/incidents` |
| 事件详情 | `GET /api/v1/incidents/{id}` |
| 报告事件 | `POST /api/v1/incidents` |
| 候选处理人（管理员） | `GET /api/v1/incidents/assignees` |
| 分派/重新分派 | `POST /api/v1/incidents/{id}/assignment` |
| 调查/解决/关闭 | `POST /api/v1/incidents/{id}/transitions` |
| 调查备注 | `GET / POST /api/v1/incidents/{id}/notes` |
| 状态历史 | `GET /api/v1/incidents/{id}/history` |
| 变更列表 / 草稿创建 | `GET / POST /api/v1/changes` |
| 变更详情 / 草稿修改 | `GET / PUT /api/v1/changes/{id}` |
| 提交审批 | `POST /api/v1/changes/{id}/submit` |
| 审批 / 审批记录 | `POST / GET /api/v1/changes/{id}/reviews` |
| 开始实施 / 结果 | `POST /api/v1/changes/{id}/implementation/start` / `result` |
| 变更状态历史 | `GET /api/v1/changes/{id}/history` |
| 全局运营统计 | `GET /api/v1/dashboard/summary` |
| 审计日志分页、筛选（管理员） | `GET /api/v1/audit-logs` |
| 审计详情（管理员） | `GET /api/v1/audit-logs/{id}` |
| 服务状态 | `GET /actuator/health` |

开发模式下，浏览器请求同源 `/api`，Vite 将其转发给后端。健康检查同样经代理转发。

JWT 保存在当前标签页的 `sessionStorage`，不放入 URL、日志或 `localStorage`，不保存密码。退出时清除本地会话；后端当前没有服务器端注销接口。页面恢复、窗口重新获得焦点及定期刷新时会校验当前用户，角色变更由后端实时判断。

只有语言偏好使用 `localStorage` 的 `opsflow.locale.v1` 保存，不包含账号、密码或令牌。浏览器禁用存储时仍可切换语言，但不能跨刷新记忆。

用户搜索仅作用于当前页，界面已标明范围；后端尚未提供跨页搜索接口。统计中的“团队用户”为接口返回的总人数，“本页启用”“本页管理员”只统计当前页。

服务目录的状态筛选在后端执行，计数和分页针对筛选结果。负责人可为空；管理员在表单中分页选择启用的用户，不会只加载前 100 人。编辑时保留当前负责人，即使负责人不在当前选择页；原负责人已停用时需更换或清空。停用服务仍可查看详情，不提供物理删除。完整字段规范见 [服务管理 API](../backend/docs/services-api.md)。

事件流程为待分配 → 已分配 → 调查中 → 已解决 → 已关闭。管理员/开发者可报告事件；管理员选择启用的管理员或开发者分派，可代为处理整个流程；当前处理人可以调查、追加备注和解决，只有管理员能关闭。审批人只读。页面按后端返回的 permissions 显示操作按钮，后端始终重新检查权限。首次报告前需先创建至少一个启用的软件服务。

分派、状态更新和备注均提交详情的 version；发生冲突时不会覆盖记录，请关闭弹窗并刷新详情后重试。备注仅可追加，解决时必须填写解决说明，不提供事件删除或重新打开。备注和状态历史独立分页、分别显示加载错误。服务详情的“查看关联事件”链接打开对应服务的全部事件。完整契约见 [事件 API](../backend/docs/incidents-api.md)。

变更草稿允许资料不完整，提交前需填业务原因、风险等级、未来的计划实施时间、实施计划及回滚计划。时间用浏览器本地时区输入，发送为明确的 UTC 时间；展示使用本机时区。管理员/开发者可以申请，审批人必须是另一个具有 APPROVER 的账号，不能自审。被拒绝申请编辑后回到草稿，重提产生新的轮次，旧审批保留。

前端权限按钮来自后端 permissions，写操作携带 version。实施失败会自动创建同服务事件，变更和事件详情提供双向链接。总览按全库统计，近七天按 UTC 自然日分组，成功率只计算 COMPLETED / (COMPLETED + FAILED)；没有结束实施时显示“—”，不显示虚假的 100%。契约见 [变更及 Dashboard API](../backend/docs/changes-dashboard-api.md)。

### 审计日志使用说明

审计入口在管理员侧边栏的“审计日志 / Audit logs”，开发者和审批人没有入口，也不能直接打开 `/audit-logs`。填写筛选后点击“查询日志”，重置会清空筛选并回到第一页；刷新和分页沿用已应用条件。时间按浏览器本地时区输入，发送为 UTC，起点包含、终点不包含；动作代码精确匹配并区分大小写，可从输入建议中选择。日志按发生时间、ID 倒序排列。详情弹窗可直接切换语言，原始 JSON 与业务文本保持原文；关闭后保留列表页及筛选，不提供编辑或删除。操作人为 null 时显示“系统操作”。接口契约见 [审计查询 API](../backend/docs/audit-logs-api.md)。

### 一个人演示审批流程

1. 用管理员创建启用的软件服务，以及一个 DEVELOPER 账号和一个 APPROVER 账号。
2. 用开发者新建草稿，补齐计划并提交。
3. 退出并切换审批账号，批准（或拒绝后由开发者修改重提）。
4. 切回开发者，开始实施并记录成功或失败。
5. 失败时查看关联事件；进入“运营总览”刷新统计。

不能用同一个申请人账号审批自己的申请，即使该账号拥有多个角色。这只是账号切换，不要求多人同时操作。平台记录实施计划和结果，不自动执行发布命令。

## 浏览器端到端测试

```powershell
npx.cmd playwright install chromium
npm.cmd run test:e2e
```

测试需要 JDK 21、同级后端以及可下载 Maven 依赖的网络。启动脚本会使用配置的 JDK 或本机标准位置的 JDK 21。

测试自动启动：

1. 18081 端口上的真实 Spring Boot 接口，使用独立的内存 H2 数据库和专用测试账号。
2. 4173 端口上的前端，并将代理指向该测试后端。
3. Chromium 浏览器，执行登录、用户管理、服务管理、事件全流程、变更草稿/多轮审批/实施结果、失败事件双向链接、真实统计、管理员审计日志筛选/分页/详情/权限、跨标签页版本冲突、中英文切换及手机布局等流程。审计错误重试用例会主动中断指定请求来验证断网反馈；恢复后的请求仍访问真实测试后端。

测试不使用你的本地 PostgreSQL，不修改正式账号。测试账号仅存在于测试进程内存中，进程结束后销毁。测试专用密码不适用于本地 PostgreSQL 中的账号。

常规运行 `npm run dev` 始终连接配置的真实后端，不启用测试数据或伪接口。

## 真实 PostgreSQL 完整业务验收（显式运行）

```powershell
npm.cmd run test:acceptance:postgres
```

需要 JDK 21、已有 Chromium、本地 PostgreSQL，以及同级后端的 `application-local.yml`。数据库账号需要 CREATEDB 权限。该命令只读取现有连接配置，不输出密码；会新建随机命名的 `opsflow_acceptance_<随机值>` 临时数据库，执行现有 Flyway 迁移，用独立测试账号和 `TEST-` 服务运行真实 React → Spring Boot → PostgreSQL 流程。

验收端口为 4174 / 18082，不使用或关闭现有 5173 / 8080 服务。测试覆盖服务创建/修改及审计筛选/详情/双语/权限；事件报告、分派、调查、备注、解决、关闭；变更草稿、提交、另一账号审批、实施成功和失败；失败关联事件、双方链接、Dashboard 增量与审计操作人。

结果、截图及 HTML 报告生成在 `acceptance-results/`。运行结束会核对数据库所有权标记后删除本次临时库，并记录现有 opsflow 数据库前后的表行数。不会清空或迁移现有 opsflow 库，不会在其中留下 TEST 数据。没有自动执行真实部署、故障注入到实际服务或回滚生产配置。若清理失败，命令返回失败并在 `run-summary.json` 标明，禁止直接对现有业务库进行清理。
